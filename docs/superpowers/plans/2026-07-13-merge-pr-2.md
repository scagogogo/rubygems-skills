# Merge PR #2 to main Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development`
> Steps use checkbox (`- [x]`) syntax.

**Goal:** 将已 CI 全绿、可合并的 PR #2（`test/full-coverage` → `main`）自主合并到 `main`，并同步本地、清理已合并分支。

**Architecture:** `gh pr merge 2 --merge` 在 GitHub 侧创建 merge commit 合并 11 个提交到 `main`（保留每个任务的可追溯历史）→ `git fetch origin` 拉取合并后的 `origin/main` → 本地切到 main 并 fast-forward 到 `origin/main` → 删除已合并的远端与本地 `test/full-coverage` 分支。数据流：远端 PR → GitHub merge → origin/main → 本地 main，最后清理两端分支引用。

**Tech Stack:** git 2.x, GitHub CLI (`gh`) 2.x

**Risks:**
- 合并后本地 `main` 落后于 `origin/main` → 缓解：Task 2 Step 2 `git fetch` 后强制 reset 本地 main 到 `origin/main`
- 远端分支合并后残留 → 缓解：Task 2 Step 4 用 `gh api` 确认 PR 状态为 `MERGED` 后删除远端分支
- merge commit 的父母 SHA 包含分支头 SHA，回滚时用 `git revert -m 1` 即可 → 已记录在验证 Step

### Task 1: 选择合并策略并执行合并

**Depends on:** None
**Files:**
- Modify: 无代码改动（仅 GitHub 侧合并）

- [x] **Step 1: 确认 PR #2 仍可合并且 CI 全绿**

```bash
gh pr view 2 --json state,mergeable,mergeStateStatus,statusCheckRollup
```

Expected:
  - Exit code: 0
  - Output contains: `"state":"OPEN"`, `"mergeable":"MERGEABLE"`, `"mergeStateStatus":"CLEAN"`
  - `statusCheckRollup` 中所有 check 的 `conclusion` 为 `"SUCCESS"`（4 个：Go 1.21/1.22/1.23 + Linter）

- [x] **Step 2: 以 merge commit 方式合并 PR #2 到 main**

```bash
gh pr merge 2 --merge --delete-branch
```

说明：`--merge` 创建 merge commit 保留 11 个提交的完整历史；`--delete-branch` 让 GitHub 合并后自动删除远端 `test/full-coverage` 分支。

Expected:
  - Exit code: 0
  - Output contains: `Merged` or `Already merged` is NOT present（首次合并应成功）
  - 不含 `error` 或 `failed`

- [x] **Step 3: 验证 PR #2 状态为 MERGED**

```bash
gh pr view 2 --json state,mergedAt,mergeCommit
```

Expected:
  - Exit code: 0
  - Output contains: `"state":"MERGED"`
  - `mergedAt` 非空，`mergeCommit.oid` 非空

### Task 2: 同步本地 main 并清理分支

**Depends on:** Task 1
**Files:**
- Modify: 无代码改动（仅本地 git 操作）

- [x] **Step 1: 拉取合并后的 origin/main**

```bash
git fetch origin --prune
```

Expected:
  - Exit code: 0
  - Output contains: `origin/main` 的更新或已是最新
  - 因 `--delete-branch` 已删远端分支，`--prune` 会删除本地 `refs/remotes/origin/test/full-coverage`

- [x] **Step 2: 切换到本地 main 并 fast-forward 到 origin/main**

```bash
git checkout main && git reset --hard origin/main
```

说明：本地 `main` 在本会话开始前可能落后于合并后的 `origin/main`，用 `reset --hard` 确保完全一致。`reset --hard` 在这里是安全的——本地 `main` 没有任何未推送的独有提交（所有工作都在 `test/full-coverage` 分支上）。

Expected:
  - Exit code: 0
  - `git log --oneline -1` 输出包含 merge commit 或分支最新提交
  - `git status` 显示 `working tree clean`

- [x] **Step 3: 验证 main 包含全部 11 个工作提交**

```bash
git log --oneline origin/test/full-coverage..HEAD 2>/dev/null | head; git log --oneline -15
```

说明：远端 `test/full-coverage` 已删，第一个命令应无输出或报错（分支不存在）——这本身是合并成功的证据。第二个命令应能看到 11 个工作提交 + merge commit。

Expected:
  - Exit code: 0
  - `git log --oneline -15` 输出包含 `test(cmd): cover CLI subcommands`、`test(install): refactor for testability` 等全部 11 个提交

- [x] **Step 4: 删除本地残留的 test/full-coverage 分支**

```bash
git branch -D test/full-coverage 2>/dev/null; git branch | grep test/full-coverage && echo "STILL EXISTS" || echo "DELETED"
```

Expected:
  - Exit code: 0
  - Output contains: `DELETED`

- [x] **Step 5: 验证全量测试在合并后的 main 上仍然通过**

```bash
go test -short -race -count=1 ./...
```

Expected:
  - Exit code: 0
  - Output contains: `ok` for `cmd/rubygems`、`pkg/cache`、`pkg/install`、`pkg/models`、`pkg/repository`、`tests`、`tests/integration`
  - 不含 `FAIL`

- [x] **Step 6: 提交**
Run: 无代码变更需要提交；本 Task 仅做分支同步与清理。如 Step 5 验证通过，工作流收尾完成。
